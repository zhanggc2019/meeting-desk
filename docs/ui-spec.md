# Windows 语音转写与 AI 会议纪要工具：UI 规格

> 状态：Phase 2/5 实现基线
> 日期：2026-07-17
> 适用范围：Windows 11 x64 MVP
> 最新范围：应用只处理用户通过系统文件选择器导入的本地音频，不提供实时音频采集。桌面裸路径拖放因授权边界不清晰而禁用；浏览器 mock 中的拖放只用于前端交互测试。

## 1. 设计结论

MVP 采用单窗口、左侧主导航、右侧工作区的企业办公布局。默认首页就是“转写工作台”，核心路径为：

```text
选择本地音频 -> 本地校验 -> 创建任务 -> 上传 -> 转写
-> 生成会议纪要 -> 本地保存 -> 查看/搜索/复制/导出
```

单文件与批量文件共用一套流程：一个文件对应一个独立任务，批量处理只是一次创建多个任务。界面不采用仪表盘卡片墙、营销首屏、装饰性渐变或虚假波形；文件、任务和历史记录主要使用分区、列表、表格和清晰的状态文字。

### 1.1 视觉命题

安静、精确、可信的 Windows 企业工具：以冷灰白工作面、深色文字和单一蓝色操作色建立秩序；绿色、琥珀色和红色仅表示成功、等待/警告和失败/危险操作。

### 1.2 内容计划

1. 首屏直接提供文件选择和最近任务，不放欢迎页或宣传文案。
2. 文件审阅区先回答“哪些文件可以处理、将使用哪个模板”。
3. 任务页优先回答“进行到哪里、是否需要我处理”。
4. 历史页负责本地搜索和已完成会议管理。
5. 详情页先展示可行动的结构化纪要，再展示完整转写。
6. 设置页只呈现中立 Provider 配置和安全状态，不暴露供应商私有字段。

### 1.3 交互命题

- 文件加入和移除使用 120–180 ms 的轻量列表过渡，保持批量操作的空间关系。
- 任务状态更新只高亮发生变化的行和阶段，约 160 ms 后恢复，不滚动或抢占焦点。
- 页面切换使用短淡入；所有动画遵循 Windows“减少动画”或 `prefers-reduced-motion`。

## 2. 信息架构

### 2.1 一级导航

| 导航项 | 默认路由建议 | 责任 |
| --- | --- | --- |
| 转写工作台 | `/workspace` | 默认首页；选择/拖放文件、校验、选择模板并创建任务 |
| 任务队列 | `/tasks` | 查看单个或批量任务的阶段、错误、取消和重试 |
| 会议记录 | `/meetings` | 搜索、查看、复制、导出和删除已保存会议 |
| 设置 | `/settings` | 配置 ASR/纪要 Provider、密钥状态、超时和重试 |

会议详情使用 `/meetings/:meetingId`。任务详情可使用 `/tasks/:taskId` 或任务页右侧详情面板，Phase 1 只选择一种，不同时实现两套模式。

### 2.2 全局窗口结构

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ Windows 原生标题栏：应用名称                                      _ □ × │
├──────────────┬──────────────────────────────────────────────────────────┤
│ 产品标识     │ 页面标题                                  页面主要操作  │
│              ├──────────────────────────────────────────────────────────┤
│ 转写工作台   │                                                          │
│ 任务队列  2  │                    当前页面工作区                         │
│ 会议记录     │                                                          │
│              │                                                          │
│              │                                                          │
│ 设置         │                                                          │
├──────────────┴──────────────────────────────────────────────────────────┤
│ 仅在需要时出现的全局状态条：网络不可用 / 本地数据清理失败               │
└─────────────────────────────────────────────────────────────────────────┘
```

- 首版优先使用原生标题栏，减少自定义窗口拖拽、缩放和辅助功能风险。
- 默认窗口建议为 `1180 × 760`，最小工作尺寸建议为 `960 × 640`；最终值须在 Phase 1 实机验证。
- 窗口较窄时，导航收窄为图标加工具提示；正文仍保留可见页面标题。
- 任务数量徽标只表示需要关注的活动/失败任务数量；数字不能成为唯一状态提示。
- 全局状态条不放“取消全部”等危险操作，只提供前往相关页面的入口。

## 3. 视觉与文案系统

### 3.1 基础视觉

- 字体使用 Windows 系统字体栈，以 `Segoe UI`、`Microsoft YaHei UI` 为主，不下载外部字体。
- 正文以 14 px 为基准，辅助文字不小于 12 px；页面标题 24 px，区块标题 16–18 px。
- 主色只使用一种稳定蓝色；中性色承担大部分层级。语义色不能用于装饰。
- 默认使用平面背景和分隔线；不为每个区块同时添加边框、阴影和圆角。
- 建议按钮高度 36–40 px，图标按钮命中区至少 32 × 32 px；危险操作必须有文字标签或明确的辅助名称。
- 图标只辅助扫描，始终与文本或可访问名称配对。可以采用单一轻量图标库，不混用多套风格。

颜色值由 Phase 1 token 文件确定并通过实际对比度检查；本文不把未经测试的色值声明为合规。

### 3.2 状态文案

任务阶段使用中立 DTO 到中文文案的一处集中映射，禁止各页面自行拼接：

| 后端状态/阶段 | 用户可见文案 | 默认行为 |
| --- | --- | --- |
| `queued` | 等待处理 | 可取消 |
| `preparing` | 正在检查文件 | 不显示虚假百分比 |
| `uploading` | 正在上传 | 有可信上传进度时才显示百分比 |
| `transcribing` | 正在转写 | 显示阶段或不确定进度 |
| `validating_transcript` | 正在校验转写结果 | 短阶段，不弹出对话框 |
| `summarizing` | 正在生成会议纪要 | 显示阶段或不确定进度 |
| `validating_minutes` | 正在校验会议纪要 | 不显示模型原始响应 |
| `saving` | 正在保存 | 事务成功后才能进入完成 |
| `retry_wait` | 等待重试 | 仅在后端提供时间时显示下一次重试时间 |
| `cancel_requested` | 正在取消 | 禁用重复取消 |
| `interrupted` | 处理已中断 | 根据后端能力提供重试或取消 |
| `completed` | 已完成 | 提供查看会议 |
| `failed` | 处理失败 | 展示安全错误和允许的下一步 |
| `cancelled` | 已取消 | 不暗示结果已经保存 |

状态不能只靠颜色表达；必须同时有文字和图标/形状。Provider 不提供精确进度时只展示阶段，不根据文件大小或预计时长伪造百分比。

### 3.3 产品文案原则

- 使用操作语言，例如“选择音频文件”“正在生成会议纪要”“检查 API 配置”，不使用营销口号。
- 不把 `speaker 1` 自动写成真实参会人；未知参会人显示“未识别参会人”。
- 错误只展示 `TaskError.safeMessage` 和安全错误码；不展示原始 exception、响应 body、Authorization、完整本地路径或请求内容。
- 复制成功提示写“已复制”，不在 Toast 中重复会议正文。
- 文件校验结论使用“可处理、文件为空、格式不支持、文件无法读取”等明确文字，不只放图标。

## 4. 转写工作台

### 4.1 初始状态

```text
转写工作台                                         [查看任务队列]
选择本地音频并生成结构化会议纪要

处理方式
[ 单个文件：一次处理 1 个录音 ] [ 批量处理：一次导入多个录音 ]

┌──────────────────────────────────────────────────────────────┐
│                 将音频文件拖到此处                           │
│             或  [按当前模式选择音频文件]                     │
│      支持格式和限制以当前转写服务的校验结果为准               │
└──────────────────────────────────────────────────────────────┘

最近任务
文件名                   当前状态             更新时间          操作
项目周会.mp3             正在转写             14:32             [查看]
```

- “单个文件 / 批量处理”是显式模式开关，避免用户只能通过多选行为猜测批量能力。
- 单文件模式的 Windows 文件对话框只能选择一个文件；批量模式允许多选并可继续追加。
- 两种模式都只通过受信任的桌面文件对话框接收音频，复用相同的后端校验和任务流程。
- 文件选择按钮可用键盘聚焦并通过 Enter/Space 打开文件对话框。
- 初始页不写死真实 Provider 尚未验证的文件大小、时长或格式上限；只显示后端公开的 capability 或笼统说明。
- 最近任务只显示安全文件名、状态和时间，不显示完整路径、转写正文或远程响应摘要。
- 没有可用 Provider 时仍允许选择文件并完成本地校验；创建云端任务前提示前往设置或切换 Mock。

### 4.2 文件入口安全边界

- Tauri 桌面端只通过 Rust 系统文件对话框取得用户授权路径。
- 不向前端暴露接受任意 `PathBuf` 的 IPC，也不持久化或记录绝对路径。
- 浏览器 mock 可模拟拖放以测试审阅列表，但该行为不代表桌面产品能力。

## 5. 文件审阅与批量导入

文件加入后，工作台切换为审阅状态：

```text
本批次文件                                      [继续添加]
4 个文件 · 3 个可处理 · 1 个校验失败 · 合计 115 MB

文件名                    大小       时长       校验状态          操作
项目周会.mp3              31 MB      32:29      可处理            [移除]
客户访谈.wav              84 MB      46:02      正在校验          [取消校验]
空文件.wav                0 B        —          文件为空          [移除]

会议纪要模板
[标准会议纪要                                      ▾]

                                  [清空列表] [处理 2 个可用文件]
```

### 5.1 文件校验

- 每个文件先由后端校验存在性、可读性、非空、格式、大小、时长和 Provider capability；前端不自行推测可上传性。
- 校验中显示逐行状态，其他文件仍可完成；校验失败不阻断可用文件。
- 校验失败的文件保留在列表中并显示原因，但不计入提交数量。
- 文件名用于显示；完整路径只停留在受信任后端。文件名过长时中间省略，悬停提示也不显示完整路径。
- 文件大小和时长缺失时显示“—”，不编造为 0。
- 相同文件或已有活动任务由后端 artifact/task 幂等规则判断；UI 只展示“已有处理中任务”或“已存在记录”的安全结果，不按文件名自行判断。

### 5.2 批量行为

- 批量入口必须在未选择文件时可见，并明确说明“每个音频创建独立任务，单个失败不影响其他文件”。
- 当前列表非空时锁定模式切换并提示先清空，避免切换模式造成受管暂存副本或审阅状态意外丢失。
- “继续添加”形成的累计列表在每次复制前和最终提交时都由后端复核当前暂存量、文件数和总大小，不能通过多次选择绕过资源限制。
- 重复音频显示为不可提交项，不复用活动任务的可释放 artifact；移除候选不得清理活动任务正在使用的暂存文件。
- 一个文件对应一个独立任务。部分任务创建失败时逐行显示结果，不能把整个批次标成全部成功或全部失败。
- 默认模板应用于本批次所有可用文件。MVP 不提供复杂的逐文件 Prompt 编辑器；若允许逐文件改模板，只能使用已验证的模板 ID。
- 提交按钮显示将创建的任务数量；校验仍在进行时只提交已明确可用的文件，并在按钮文案中如实显示数量。
- “清空列表”只清除尚未提交的前端审阅项，不删除已创建任务或本地历史。
- 提交成功后导航到任务队列并保持本批次筛选；批量任务完成不会强制跳转到任一会议详情。
- 大文件切片、转码或异步上传由后端 Provider 能力决定，UI 只展示真实阶段，不暴露实现细节。

### 5.3 审阅状态

- **空列表**：恢复初始文件选择区。
- **校验中**：行级忙碌状态，不覆盖整个页面。
- **全部不可用**：禁用提交，页内说明“没有可处理的文件”，保留逐项原因。
- **部分可用**：允许提交可用项，按钮明确数量；不可用项留在审阅区供处理。
- **校验服务失败**：展示安全错误和“重新校验”，不丢失已选择的安全文件引用。

## 6. 任务队列

### 6.1 页面结构

```text
任务队列                                [全部] [进行中] [失败] [已完成]

文件名                   当前阶段          尝试次数       更新时间       操作
季度复盘.wav             正在生成纪要      1 / 3          14:42          [取消]
客户访谈.mp3             等待重试          2 / 3          14:41          [查看]
周会.wav                 处理失败          1 / 3          14:30          [重试]
```

- 列表按“需要关注、活动中、最近更新”排序；筛选状态可通过路由查询参数保留，但不写入业务数据库。
- 没有可信总进度时，行内仅显示当前阶段和不确定进度指示。只有后端明确提供可验证的上传比例时才显示数字。
- `retry_wait` 显示后端给出的下一次重试时间；若无该数据，只显示“等待重试”，不自行倒计时。
- 点击行打开任务详情，展示时间线、当前 attempt、安全错误和可执行操作；不展示完整请求/响应、Authorization 或会议全文。
- 完成任务的主操作为“查看会议”。任务完成事件不抢焦点，也不自动切换页面。

### 6.2 取消上传、转写和总结

- 活动任务是否可取消由后端提供的 `availableActions` 或等价能力决定，UI 不按阶段自行假定。
- 用户点击取消后先确认：“取消后将停止后续处理；已发送到云端的请求可能已产生用量。”
- 确认后任务进入 `cancel_requested`，按钮显示“正在取消”并禁用重复操作。
- 上传、转写或总结已经到达云端时，取消可能存在延迟；UI 只在后端确认后显示“已取消”。
- 取消成功不自动删除用户原始本地文件；临时副本或上传缓存的清理由后端策略负责。
- 批量场景默认逐任务取消。MVP 不提供容易误触的“取消全部”；后续若增加，必须展示任务数量并二次确认。

### 6.3 失败与重试

- 重试只在 `retryable` 或 `interrupted` 且后端允许时出现。
- 401/403 默认提供“前往设置”，不提供盲目重试；429 显示服务端等待策略；timeout/500 按配置有限重试。
- 重试沿用原文件引用和模板配置，是否重新上传由 Provider adapter 决定；UI 不声称从失败阶段精确续传。
- 重试提交后立即禁用按钮，直到收到新的持久化任务状态。
- 文件已经不可读、被移动或被删除时，显示“重新选择文件”，不能把旧路径暴露给用户或日志。

### 6.4 任务详情时间线

时间线只展示持久化的真实阶段：等待、检查文件、上传、转写、校验转写、生成纪要、校验纪要、保存。未到达的阶段显示“尚未开始”，未执行的阶段显示“未执行”；失败点带安全错误说明。页面刷新或应用重启后仍以 repository 状态重建，不依赖前端内存。

## 7. 会议记录页

### 7.1 页面结构

```text
会议记录                                             [选择音频文件]
在本机查找已保存的会议

[搜索标题、日期或会议内容________________] [日期筛选]

会议标题               时间          时长       状态             操作
产品项目周会           今天 10:00    42 分钟    已完成           [打开] [⋯]
```

- “选择音频文件”返回转写工作台并打开系统文件对话框，是历史空状态与正常状态都可见的入口。
- 搜索仅查询本地 repository，不调用云端；输入建议 250–350 ms 防抖，并取消或忽略过期查询。
- 会议记录使用紧凑列表/表格，默认按更新时间倒序；标题缺失时显示“未命名会议”，不回退显示完整路径。
- 行点击打开详情；行内更多菜单提供复制摘要、导出 Markdown、删除。菜单操作必须可由键盘到达。
- 删除必须确认，并说明删除范围。后端未确认成功时不得从列表永久消失。

### 7.2 页面状态

- **首次空状态**：标题“还没有会议记录”，正文说明可选择已有音频文件生成纪要，提供“选择音频文件”。
- **搜索无结果**：显示“没有找到匹配的会议”，保留查询内容并提供“清除筛选”。
- **加载**：首次读取使用与表格结构一致的骨架；刷新已有内容时保留旧内容并显示轻量刷新状态。
- **读取失败**：工作区内显示安全错误、错误码和“重试”；导航与设置仍可使用。

## 8. 会议详情页

### 8.1 信息层级

```text
[返回会议记录]
产品项目周会                         [复制摘要] [导出 Markdown] [⋯]
2026-07-17 10:00–10:42 · 42 分钟 · 参会人未识别

[会议纪要] [完整转写]

会议摘要
……

主要议题
1. ……

关键结论
……

决策事项
事项                         结果/说明
……

待办事项
事项                  负责人          截止日期
……                    未指定          未指定

风险和问题
……
```

- 标题、会议时间和参会人在页首形成上下文；未知信息明确显示“未识别/未指定”，不由 UI 猜测。
- 使用“会议纪要/完整转写”两个页签减少超长页面负担。切换页签不发起云端请求。
- 纪要按摘要、主要议题、关键结论、决策事项、待办事项、风险和问题的稳定顺序展示。
- 列表为空时显示“未提取到相关内容”，不能隐藏标题造成“数据没有加载”的误解。
- MVP 不支持直接编辑模型输出，避免产生未定义的持久化语义。
- 每个结构化区块可提供“复制本节”，且必须能通过键盘聚焦发现。复制内容来自已保存数据，不从 DOM 拼接隐藏内容。
- 模型输出按纯文本渲染；即使内容看似 Markdown，也不执行任意 HTML 或脚本。

### 8.2 完整转写

- 有 segments 时按时间戳和 speaker label 渲染；缺少 speaker、时间戳或 confidence 时省略对应列，不制造数据。
- 只有后端提供低置信度信息时才显示提示；不根据标点或文本长度自行推断。
- 纯文本转写使用易复制的连续正文并保留换行，提供“复制完整转写”。
- 长转写的虚拟化或分段方案必须验证复制、搜索和屏幕阅读器行为；MVP 可以先使用简单的渐进渲染。
- 纪要与转写加载错误相互隔离，错误区不得包含原始响应或本地绝对路径。

### 8.3 导出与删除

- 导出按钮调用后端系统保存对话框。成功只提示文件名或“导出完成”；用户取消保存不是错误。
- 导出失败保留当前页面状态并提供重试，不在前端自行写文件。
- 导出的 UTF-8 Markdown 按稳定章节顺序包含结构化纪要和完整转写。
- 删除入口位于更多菜单并二次确认。只有后端确认结果后才返回会议列表；存在待清理项时展示后端提供的安全状态。

## 9. 设置页

设置页分为“语音转写”“会议纪要”“模板与本地数据”三个纵向区块，不使用多列卡片墙。

每个 Provider 区块包含：

- Provider 类型：`OpenAI-compatible`、`Mock` 等由后端能力清单提供的中立名称。
- Endpoint、模型名、连接/请求超时、最大重试次数和并发限制。
- API Key 输入：未配置时可填写；已配置时只显示“已安全保存”，可以“替换”或“删除”，绝不显示原值。
- “测试连接”按钮和安全结果。测试时只显示阶段、HTTP status/安全错误码，不显示 request/response body。
- 未保存改动提示与“保存设置”；离开有未保存改动的页面时使用应用内确认。

模板区显示后端提供的可用模板名称和用途说明。MVP 至少支持“标准会议纪要”，可以提供项目周会、客户沟通等内置模板；不提供任意 Prompt 编辑器。

Mock 模式有明确的“仅用于演示和测试”标识，并允许选择后端公开的安全场景，如成功、超时、401、429、500。UI 不自行伪造 HTTP 行为。

本地数据区提供删除单条或清理全部应用数据的入口。清理全部数据必须二次确认，并明确是否同时删除应用保存的凭据；默认不能含糊地把两者合并。

## 10. 加载、空、错误与反馈模式

### 10.1 加载

- 预计少于约 300 ms 的命令不先闪烁加载器；超过阈值再显示局部忙碌状态。
- 页面首次加载用结构匹配的骨架，按钮命令用按钮内状态；不使用覆盖整窗的 Spinner 阻断不相关导航。
- 已有内容刷新时保留旧数据并标注“正在更新”，禁止为了刷新造成整页跳动。
- 文件提交、任务取消、设置保存等关键命令锁定重复提交，等待后端最终状态。

### 10.2 空状态

- 工作台没有文件：显示文件选择入口。
- 无任务：显示“当前没有处理任务”，提供“选择音频文件”。
- 无会议：显示“还没有会议记录”，提供文件选择入口。
- 纪要字段为空：就地显示“未提取到相关内容”。
- 转写为空：视为流程错误，不显示空白但已完成的详情。
- 搜索为空：保留搜索上下文并提供清除筛选。

### 10.3 错误

- 表单校验错误紧邻字段；命令失败显示在对应操作区；后台任务失败进入任务列表和非打断式通知。
- Toast 只用于短暂确认，不承载长错误、正文或唯一恢复入口。
- 错误展示顺序：用户可理解的 `safeMessage`、安全错误码、建议动作。HTTP status 只在有诊断价值时显示。
- 可恢复错误提供“重试”；配置错误提供“前往设置”；文件错误提供“重新选择文件”；不可恢复错误不显示无效按钮。
- 网络离线通过全局状态条提示，活动任务最终状态仍以后端为准。

## 11. 键盘、辅助功能与 Windows 行为

### 11.1 键盘

| 快捷键 | 行为 | 限制 |
| --- | --- | --- |
| `Ctrl+O` | 打开可多选的音频文件对话框 | 对话框已打开时不重复触发 |
| `Ctrl+F` | 聚焦当前页搜索 | 无搜索框页面不拦截系统行为 |
| `Ctrl+E` | 导出当前会议 | 仅详情页且数据已保存时生效 |
| `Escape` | 关闭菜单或对话框 | 绝不能直接取消任务或删除会议 |
| `F6` | 在导航、页面标题区、主工作区间循环 | 遵循 Windows 常见区域导航 |

不设置无修饰键的危险全局快捷键。按钮支持标准 Enter/Space 激活；对话框中 Enter 的默认操作不得是取消任务或删除数据。

### 11.2 可访问性

- 文件选择入口可点击、可聚焦并具有明确的 accessible name。
- 所有交互元素有可见焦点；焦点顺序与视觉顺序一致，页面切换后聚焦页面标题。
- 图标按钮、状态点、进度指示和页签具有明确的 accessible name、role 和当前状态。
- 文件校验、任务完成/失败可以使用节制的 live region；频繁上传进度事件不逐条播报。
- 对话框打开后聚焦标题或首个安全控件，关闭后恢复到触发元素。危险确认使用明确动词，如“取消任务”“删除会议”。
- 文本和控件对比度、键盘操作、200% 缩放、Windows 高对比度和减少动画纳入后续验证；未实测前不得宣称符合 WCAG。
- 颜色、图标和位置不能成为唯一状态信号。表格具有标题单元格；表单字段有持久标签，不以 placeholder 替代。

## 12. 前端状态与安全边界

- SQLite/Rust repository 是会议、任务和文件 artifact 状态的唯一事实源。Zustand 只保存导航折叠、筛选、模板选择和短期表单草稿等临时 UI 状态。
- 不把 API Key、完整转写、完整纪要、绝对文件路径写入 `localStorage`、`sessionStorage`、URL、错误监控 breadcrumb 或普通日志。
- 前端不能直接请求 ASR/LLM；所有带凭据网络请求由 Rust Provider 层执行。
- 前端只能接收 `secretConfigured: boolean` 等公开设置，不能提供“读取已保存 Key”的方法。
- 文件选择结果应尽快转换为不透明 `AudioArtifactRef`；前端业务组件只消费安全文件名、大小、时长和校验状态。
- 页面只消费中立 DTO 和 `TaskError.safeMessage`。Provider 私有字段、HTTP body 和底层 exception 不得穿过 IPC。
- 事件监听在组件卸载时解除；重复事件或页面重新挂载不能重复创建任务。收到事件后以后端 revision/updatedAt 为准，必要时重新读取详情。
- 敏感正文只在用户主动打开详情时进入对应页面内存；开发期不得在日志或测试快照中保存真实会议正文。

## 13. 组件边界建议

Phase 1 保持轻量：React Router 负责页面，Zustand 只负责临时 UI，Vitest + Testing Library 负责行为测试；不引入全套企业组件框架、复杂工作流引擎或第二套远程缓存状态机。

```text
frontend/src/
├─ app/
│  ├─ AppShell.tsx
│  ├─ router.tsx
│  └─ providers.tsx
├─ pages/
│  ├─ WorkspacePage.tsx
│  ├─ TasksPage.tsx
│  ├─ MeetingsPage.tsx
│  ├─ MeetingDetailPage.tsx
│  └─ SettingsPage.tsx
├─ components/
│  ├─ ui/                    # Button、Dialog、Field、Tabs、Table 等无业务原语
│  ├─ AppNavigation.tsx
│  ├─ PageHeader.tsx
│  └─ AsyncState.tsx
├─ features/
│  ├─ imports/               # 文件选择、校验和批量创建
│  ├─ tasks/                 # 队列、时间线、取消、重试和错误操作
│  ├─ meetings/              # 列表、搜索、纪要/转写呈现、复制和导出入口
│  └─ settings/              # Provider 表单、模板和公开密钥状态
├─ services/
│  ├─ desktopClient.ts       # 类型化命令/事件边界
│  └─ mockDesktopClient.ts   # 前端行为测试使用，不伪造真实 Provider 成功
├─ stores/                   # 仅临时 UI 状态
├─ contracts/               # Lead 统一 DTO 的前端导出/适配，不复制业务 Schema
└─ test/                     # 脱敏 fixture、render helpers、a11y helpers
```

组件职责：

- `AppShell` 只负责导航、路由出口、全局网络状态和错误边界，不查询完整正文。
- 页面组件负责数据装配和页面级状态；业务组件通过 typed hooks/client 收发 DTO。
- `components/ui` 不知道文件、会议、任务或 Provider；不得在原语中内置业务状态。
- `FileDropzone` 只处理可访问交互并调用 desktop client，不读取文件内容或记录路径。
- `ImportReviewList` 只呈现后端校验结果，不自行判定 Provider 兼容性。
- `TaskStatus`/`TaskTimeline` 共享一处状态文案映射，避免列表和详情含义不一致。
- `MeetingMinutesView` 只渲染已校验的结构化纪要；`TranscriptView` 单独按可选 segment 能力降级。
- `ProviderSettingsForm` 只能提交替换密钥，不能读取或回显已有密钥。
- `desktopClient` 定义可替换接口；Tauri 实现和测试 mock 实现同一接口。前端 mock 只验证 UI 行为，Provider 协议 mock 仍由后端模块负责。

## 15. 跨模块 UI 契约注意事项

前端至少需要下列中立能力；字段以 Lead 最终类型为准：

| 模块 | 前端需要的安全数据/命令 | UI 约束 |
| --- | --- | --- |
| 文件 | 选择、校验、移除；安全引用、文件名、MIME、大小、时长、校验结果 | 仅系统文件对话框授权，不读取正文，不持久化完整路径；上限来自 capability |
| 任务 | task `id/meetingId/status/stage/attempt/error/timestamps`；列表、详情、重试、取消事件 | error 只用 `safeMessage`；进度可空；操作以后端能力为准 |
| 会议 | 列表摘要、详情、搜索、删除、复制数据、导出 | 完整转写只在详情读取；删除/导出由后端完成 |
| 纪要 | versioned `MeetingMinutes` 与可选 transcript segments | 只渲染已校验数据；未知值不补造 |
| 设置 | Provider public settings、capabilities、模板列表、保存/测试/删除 secret | 只能得到 `secretConfigured`，不能读回 secret |

建议事件包含单调 `revision` 或可靠 `updatedAt`，便于 UI 忽略乱序事件；若后端暂不提供，事件到达后按 ID 重新读取当前状态。这个字段是集成建议，不是 Phase 0 已实现事实。

后端建议提供 `availableActions` 或等价字段，明确任务当前是否允许 `cancel/retry/openMeeting/reselectFile`，避免前端复制状态机规则。

## 16. 可测试验收点

下列编号是 UI 层补充标准；已自动化部分见 `docs/test-plan.md`，Windows 实机项仍需按清单验收。

### 16.1 路由与工作台

- **UI-BOOT-01**：无 Key、无历史时可进入工作台、任务、会议记录和设置页，空状态不崩溃。
- **UI-NAV-01**：键盘可遍历一级导航，当前页面有文字与语义状态；页面切换后焦点落在页面标题。
- **UI-FILE-01**：点击和键盘均可打开多选文件对话框；桌面端不接受裸路径拖放。
- **UI-FILE-02**：选择单个、多个、不支持对象时分别显示正确反馈，绝对路径不出现在 UI、store、日志或快照。
- **UI-FILE-03**：文件为空、不可读、格式不支持、超出 capability、校验失败均逐项显示且不进入可提交数量。
- **UI-BATCH-01**：单文件与批量文件共用一套审阅流程；部分校验/创建失败不会错误地把整个批次标为成功。
- **UI-BATCH-02**：重复点击提交只发送一次创建命令；提交数量与明确可用文件数量一致。

### 16.2 任务、取消与重试

- **UI-TASK-01**：所有任务状态有文字，不依赖颜色；无可信进度时不渲染百分比。
- **UI-CANCEL-01**：上传、转写、总结阶段在后端允许时可取消；确认后只发送一次取消命令并显示 `cancel_requested`。
- **UI-CANCEL-02**：后端未确认取消前不显示“已取消”；取消失败保留任务并提供安全错误。
- **UI-TASK-02**：401/403 显示前往设置；429、timeout、500 只在后端允许时显示重试。
- **UI-TASK-03**：批量任务完成不会强制跳转；完成或失败通知不抢占焦点。
- **UI-RESTART-01**：应用重启后任务从 repository 恢复；活动任务显示后端返回的 `interrupted` 或真实状态。

### 16.3 历史与详情

- **UI-MEETING-01**：会议列表加载、空、搜索无结果、读取失败四种状态有组件测试。
- **UI-SEARCH-01**：搜索调用本地 client；快速连续输入不会让旧响应覆盖新结果，且不触发云端 Provider。
- **UI-DETAIL-01**：九类会议信息和完整转写能显示；空 participants/action owner/due date 使用诚实占位。
- **UI-DETAIL-02**：纪要加载失败与转写加载失败相互隔离；任一页签失败不使整个详情不可用。
- **UI-COPY-01**：复制区块/全文成功只显示通用反馈，测试快照和日志不包含真实正文。
- **UI-EXPORT-01**：导出成功、用户取消、后端失败均有明确且不泄露正文的反馈；Markdown 章节顺序稳定。

### 16.4 设置、安全与辅助功能

- **UI-SECRET-01**：已配置密钥只显示布尔状态；DOM、UI store、URL 和 IPC 查询响应不包含密钥原值。
- **UI-ERROR-01**：页面仅渲染 `safeMessage`/安全错误码；含敏感 header/body 的底层错误不会出现在 UI 或普通日志。
- **UI-A11Y-01**：核心流程完全可用键盘操作；Escape 不会直接取消任务或删除会议。
- **UI-A11Y-02**：文件选择、按钮、页签、对话框、表格、状态和错误具有可访问名称/角色；频繁进度不会反复播报。
- **UI-A11Y-03**：200% 缩放、Windows 高对比度、减少动画进行实机验证，失败项明确记录，不预先宣称通过。
- **UI-STATE-01**：历史和任务状态不能从 Zustand/localStorage 伪造完成；重新加载后以持久化数据为准。

## 18. 配置引导、扩展模板与 Markdown 预览

- 工作台在允许创建任务前读取转写和纪要两个 Provider 的公开就绪状态；缺少 API 地址、模型名或 Key 时，分别显示缺项与“前往设置”入口。
- Mock 必须标记为“体验模式”，用户需要明确选择后才可创建 Mock 任务，不能让 Mock 结果看起来像真实 FunASR/LLM 输出。
- 视觉采用纸张白、冷灰和单一蓝色操作色，强调文件、状态、正文和编辑预览，不使用聊天气泡、对话输入框或仿 ChatGPT 居中对话布局。
- 模板选择展示 11 个内置模板的名称和适用说明；`adaptive` 只允许模型调整统一 MeetingMinutes Schema 中各章节的内容侧重点。
- 会议详情提供“结构化纪要 / 完整逐字稿 / Markdown 预览”页签。预览文本由 Rust 端与文件导出共用的渲染器生成，再通过禁用原始 HTML 的 Markdown 组件渲染，避免预览与导出漂移。
